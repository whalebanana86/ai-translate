## 원인

## 측정 (로컬 Hy-MT2 1.8B, 앱과 같은 샘플링, 하네스는 저장소 밖)

| 지시 방식 | 평서문 합니다체 | 질문·명령 | 짧은 조각 | 지시가 새어 나옴 |
|---|---|---|---|---|
| 지금(지시 없음) | 25/50 (해요 18, 해라 2) | 거의 해요 | 그대로 | 0 |
| 사용자 메시지에 한국어 지시 | 57/60 | 해요 많음 | **망가짐**: "Um" → "네, 이해했습니다. 모든 문장이 합니다체로…", "No." → "1입니다.\n2입니다…" | 있음 |
| 사용자 메시지에 질문 규칙까지 | - | - | 지시문을 번역해 출력("평서문은 '입니다'로 끝납니다") | 있음 |
| 앞에 합니다체 예시 두 번 | 개선 적음 | 해요 | 그대로 | 0 |

| 시스템 메시지 + 질문(-습니까?) | 46/50 | 그대로 | 그대로 | 0 |

모델 채팅 형식에 시스템 메시지가 있다(`<｜hy_begin▁of▁sentence｜>{시스템}<｜hy_place▁holder▁no▁3｜><｜hy_User｜>…`).
번역 프롬프트는 모델 카드 그대로 두고 문체만 시스템 메시지로 준다.

## 설계

- `TranslationRequest.style`: 문체 지시(영어 문장, 앱이 정한다. 페이지 글이 아님). nil이면 지금과 같다(JSON에도 넣지 않음)
- `TargetLanguage.subtitleStyle`: 한국어만 "Write every Korean translation in the formal polite speech level (합니다체)."
- 로컬: 문체가 있으면 시스템 메시지로. CLI(Claude·Codex): JSON에 style을 넣고 시스템 프롬프트에 "style이 있으면 그 문체로"를 더한다
- `RegionTranslator.translate(_:to:style:)`. 렌즈는 계속 바뀌는 화면(영상)일 때만 `subtitleStyle`을 넘긴다 (사용자 선택: 영상 자막만)
- 한계: 질문·명령은 해요체("~나요?", "~보세요")로 남는 경우가 많다(지시해도 바뀌지 않고, 질문 규칙을 넣으면 평서문이 나빠짐).
  번역 기억은 문체를 구분하지 않아, 문체 지시 전에 번역해 기억한 같은 자막은 그 번역을 쓴다
