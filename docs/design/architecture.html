변화 감지

언제 다시 읽나

OCR은 비싸고 지문 비교는 쌉니다. 그래서 화면 변화는 축소본으로 보고, 바뀐 뒤 멈췄을 때만 글을 읽습니다.

왜
  • 스크롤 중에는 지난 번역을 숨김 움직인 글 위에 지난 번역이 남지 않게 했습니다(TASK-041).
  • 영상은 바뀌는 중에도 읽음 멈추기만 기다리면 자막을 영영 못 읽는다는 사용자 보고(2026-11-02).
  • 포인터가 렌즈 위면 0.15초 0.5초 간격이면 메뉴가 열린 뒤 지난 번역이 메뉴를 덮었습니다(TASK-072).

번역 엔진

빠른 것보다 맞는 것

엔진 후보를 같은 화면으로 재고, 속도와 품질 점검을 함께 봤습니다.

왜
  • Hy-MT2 1.8B 1~2B 크기에서 번역 특화·한일중 지원·Apache-2.0을 모두 만족한 유일한 모델(TASK-014).
  • MLX로 실행 이 맥에서 가장 빨랐고(TASK-015), MLX Swift로 앱 안에 바로 넣었습니다. 그래서 Apple Silicon만 지원합니다.
  • CLI 엔진 사용자가 이미 로그인한 Claude Code·Codex를 씁니다. 출시 전에는 API 키 엔진이 필요합니다.

저장

DB 대신 파일 두 종류

서버도 DB도 없습니다. 번역 기억 JSON, 모델 파일, 설정 값(UserDefaults)이 전부입니다.

왜
  • 다시 번역하지 않기 원문과 언어가 같으면 엔진을 부르지 않아 시간과 사용량을 아낍니다.
  • 지울 수 있게 설정의 '번역 기억 지우기'가 파일과 열린 렌즈의 기억을 함께 지웁니다.
  • 모델은 사용자가 받기 약 1GB라 자동으로 받지 않습니다(사용자 결정).

배포: App Store를 쓰지 않는 이유

사람이 꼭 볼 곳

바꾸면 조용히 깨지는 네 곳

테스트가 다 통과해도 사용자 쪽에서 깨질 수 있는 변경입니다. 에이전트가 바꿨다면 사람이 확인합니다.

저장 형식

번역 기억 JSON 필드·파일 이름, 설정 키, 저장되는 엔진·언어 값, 번들 ID

옛 파일을 못 읽으면 오류 없이 빈 기억이 됩니다. 번들 ID를 바꾸면 설정·동의·권한이 처음 상태로.

통신 형식

요청 JSON, 출력 스키마, 시스템 프롬프트, CLI 응답 모양

CLI가 업데이트되면 응답이 바뀔 수 있습니다. Live 테스트로 다시 확인합니다.

공개 인터페이스

TranslationProvider, TextGenerating, 기본 단축키 ⌘⇧1

API 키 엔진(BYOK)이 붙을 자리라, 바꾸면 모든 엔진이 함께 바뀝니다.
